CareerBot deployment candidate. Only the lowercase page filenames used by the
application flow are retained.

IMPORTANT AUTH SETTING
----------------------
If you want Sign Up to create an immediate session for a college/demo flow,
Supabase Dashboard -> Authentication -> Sign In / Providers -> Email ->
Confirm email should be OFF.

This is an Auth dashboard setting and is not changed by the frontend ZIP.

SECURITY NOTES
--------------
Only the Supabase publishable client key belongs in supabase.js. No service-role
key is included in this frontend package.

Supabase currently reports two advisory items that are not frontend build errors:
- Leaked Password Protection is disabled. Enable it in Supabase Auth for a more
  production-hardened password policy.
- Six authenticated SECURITY DEFINER RPCs are flagged for review. These RPCs are
  intentionally used by the application and currently validate auth.uid() and,
  for row updates, the authenticated user's ownership. Do not remove SECURITY
  DEFINER blindly because that can break the intended RPC design.

DEPLOYMENT
----------
Upload the contents of this folder to a static host. Keep the files in one folder
so the existing relative links continue to work.

Before the live demo, perform one real browser test with a fresh account:
1. Sign Up / Login
2. Profile save
3. Complete all assessment questions
4. Confirm Recommendations load
5. Open Career Details, Skill Gap, Learning Guide, and Project Ideas
6. Open a Project Workspace and save progress/links
7. Open Job Recommendations and save/view a job
8. Open CareerBot Agent and send a message
9. Logout and log back in
10. Refresh protected pages and confirm the user's saved data remains

The code/package has been statically validated and the connected Supabase schema
has been inspected. A real authenticated browser session still requires a real
user account in the deployed environment; this package does not create or embed
a test user's credentials.
